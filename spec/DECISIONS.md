# Decisions

This ledger explains why active choices exist. It is not canonical authority.

If this file conflicts with a canonical owner, the canonical owner wins and this ledger must be corrected. Historical wording and superseded process decisions remain under `archive/legacy-2026-07-16/`.

| ID | Decision | Canonical owner | Rationale / provenance |
|---|---|---|---|
| D-001 | The active repository must be self-describing and vendor-neutral. | `../CONSTITUTION.md` | A new reasoning session should understand the project without Claude-specific files, hidden prompts, or prior chat history. |
| D-002 | Keep a small explicit authority surface: README + Constitution + Objective + 12 learning-domain specs + 7 product/runtime design owners + this supporting ledger. | `../CONSTITUTION.md` | The original 16-file baseline solved learning-spec fragmentation; the user later explicitly expanded repository scope to include first-order product/runtime design. The new 23-file baseline adds only genuinely independent authority domains. |
| D-003 | Specify IELTS Academic first; add General Training as a variant overlay. | `00-PRODUCT.md`, `02-IELTS-MODEL.md` | Shared Listening/Speaking and shared learning semantics should not be duplicated. Legacy `FD-001`. |
| D-004 | Canonical learning requirements are L1-agnostic; L1/localization is an overlay. | `00-PRODUCT.md` | IELTS competence does not change by first language, while explanation/remediation may. Legacy `FD-002`. |
| D-005 | Listening, Reading, Writing, Speaking are first-class skills; grammar/vocabulary/phonology are enabling Knowledge. | `03-SKILLS.md`, `04-KNOWLEDGE.md` | Aligns the learning model with IELTS scored sections without losing teachable prerequisites. Legacy `FD-003`. |
| D-006 | Learning-domain truth is implementation-agnostic. | `00-PRODUCT.md` | Technology consumes the learning system; it does not define it. Legacy `FD-006`. |
| D-007 | Progression is mastery/evidence-based while within-band path may adapt. | `09-PROGRESSION.md` | Stable outcomes with personalized path. Legacy `LD-001`. |
| D-008 | Core tutoring/feedback/assessment may operate without mandatory human review; human verification remains optional. | `00-PRODUCT.md`, `08-ASSESSMENT.md` | Preserve scalable operation while failing closed on unsupported productive judgments. Legacy `LD-002`. |
| D-009 | Feedback timing depends on learning stage and target. | `07-PRACTICE.md` | Universal immediate feedback conflicts with retrieval, transfer, fluency, and exam-independence goals. Legacy `LD-003`. |
| D-010 | Dependencies are Required, Recommended, or Independent; hard gates must be minimal. | `06-CURRICULUM.md`, `09-PROGRESSION.md` | Preserve prerequisite integrity without making every beneficial ordering a blocker. Legacy `LD-004`. |
| D-011 | Learning Progression and Exam Preparation are independent dimensions. | `09-PROGRESSION.md` | Exam-like/higher-demand exposure can aid readiness without becoming a certification shortcut. Legacy `LD-005`. |
| D-012 | Use six learning phases: Acquisition, Consolidation, Retrieval, Transfer, Fluency, Exam Readiness. | `07-PRACTICE.md` | Stable purpose vocabulary across training patterns. Legacy `LD-006`. |
| D-013 | Skill Leaves are atomic, stable-ID capabilities; no arbitrary leaf-count target. | `03-SKILLS.md` | Atomicity serves teaching, practice, assessment, and remediation. Legacy `SK-001..003`. |
| D-014 | Knowledge uses atomic objects with explicit Knowledge→Knowledge and Skill→Knowledge dependencies. | `04-KNOWLEDGE.md` | Prerequisites must resolve to learnable knowledge rather than vague labels. Legacy `KK-001..003`. |
| D-015 | Bands 3–9 are the structured learning range; Bands 0–2 are diagnostic/external boundaries. | `05-BANDS.md` | Preserve full scale awareness without inventing a detailed sub-Band-3 curriculum. Legacy `BD-001`. |
| D-016 | Exit criteria are hierarchical where needed: task threshold → skill-band threshold → progression decision. | `05-BANDS.md` | Prevent task requirements from disappearing into vague overall mastery. Legacy `BD-002`. |
| D-017 | Listening/Reading detailed per-band abilities are Blueprint Inference unless directly supported by official IELTS evidence. | `02-IELTS-MODEL.md`, `05-BANDS.md` | Receptive public scoring does not provide the same analytic descriptor structure as Writing/Speaking. Legacy `BD-003`. |
| D-018 | Curriculum orchestrates canonical objects by reference; it does not redefine them. | `06-CURRICULUM.md` | Pathway organization must not become another learning truth layer. Legacy `CR-001`, `CR-003`. |
| D-019 | Practice Types are reusable activity patterns; concrete exercises are instances. | `07-PRACTICE.md` | Stable learning strategy with replaceable/generated content. Legacy `PR-001`, `PR-003`. |
| D-020 | Assessment Types define reusable measurement roles; concrete tests/items are instances. | `08-ASSESSMENT.md` | Measurement semantics must not live inside item collections. Legacy `AM-001`, `AM-002`. |
| D-021 | Evidence sufficiency is claim-scoped; there is no universal attempt count or global confidence cutoff. | `08-ASSESSMENT.md` | The previous `N=2` / `0.80` defaults were useful provisional heuristics but were too strong as canonical policy. Counts, recency windows, transfer requirements, and confidence thresholds require calibration for the claim/evaluator. This supersedes the earlier active wording derived from `AM-003`. |
| D-022 | Learner state is semantic, not a storage schema. | `09-PROGRESSION.md` | Runtime learning truth should survive implementation changes. Legacy `PG-001`. |
| D-023 | Each IELTS skill progresses/certifies independently; overall band is informational for learning progression. | `09-PROGRESSION.md` | Uneven profiles are normal. Supersedes the older synchronized four-skill gate. Legacy `PG-002`. |
| D-024 | Current certification may regress when new admissible evidence establishes regression; historical attainment remains. | `09-PROGRESSION.md` | Current truth and history are separate. Legacy Red-Team F2 resolution. |
| D-025 | Concrete content is reference-based and replaceable. | `10-CONTENT-MODEL.md` | Learning Units, items, stimuli, feedback, and tutoring patterns must not become parallel domain definitions. |
| D-026 | Go, Python, and TypeScript are the approved primary application languages. | `../CONSTITUTION.md` | Explicit polyglot baseline prevents accidental runtime-language sprawl. |
| D-027 | Implementation structure follows responsibility/deployable boundary, not language. | `../CONSTITUTION.md` | Avoid top-level `go/`, `python/`, `ts/` domain silos and triple modeling. |
| D-028 | Genuine cross-language boundaries have one explicit machine-readable contract owner; generated/local bindings are derived. | `../CONSTITUTION.md` | Prevent Go/Python/TypeScript mirror-schema drift. |
| D-029 | Use the same canonical domain vocabulary across languages while following language-idiomatic casing/file conventions. | `../CONSTITUTION.md` | Stable semantics, idiomatic code. |
| D-030 | Root verification must span every affected language and relevant cross-language contract. | `../CONSTITUTION.md` | A polyglot change is not verified because only one ecosystem is green. |
| D-031 | Separate Attempt → Observation → EvidenceFact → Mastery/Readiness evaluation → Progression. | `08-ASSESSMENT.md`, `10-CONTENT-MODEL.md`, `09-PROGRESSION.md` | A response is not automatically evidence; evidence is not automatically mastery. This preserves provenance and permits governed recomputation without rewriting history. |
| D-032 | Missing, conflicting, stale, and observed-below-requirement evidence are distinct epistemic states. | `08-ASSESSMENT.md`, `01-LEARNER-MODEL.md` | Unknown is not weakness; stale is not regression; conflict should not be averaged away. |
| D-033 | Assessment claim outcomes use `INSUFFICIENT_EVIDENCE`, `CONFLICTING_EVIDENCE`, `STALE_EVIDENCE`, `NOT_YET_SUPPORTED`, `SUPPORTED` rather than one readiness percentage. | `08-ASSESSMENT.md` | Required conditions should not be averaged away by stronger unrelated evidence. |
| D-034 | Adaptive planning follows GapEvaluation → ActionIntent → Learning Mechanism → Practice Type. | `09-PROGRESSION.md`, `07-PRACTICE.md` | A wrong answer should not directly map to an exercise; prerequisite, uncertainty, conflict, staleness, transfer, scaffold, and fluency problems need different interventions. |
| D-035 | Learning Mechanism and Practice Type are separate concepts. | `07-PRACTICE.md` | Retrieval, contrast, scaffold fading, transfer variation, etc. are learning processes; a Practice Type is an executable activity pattern that may combine them. |
| D-036 | Spacing applies only to suitable reviewable targets; there is no universal scheduler for every IELTS capability. | `07-PRACTICE.md`, `09-PROGRESSION.md` | Vocabulary retrieval and integrated Writing/Speaking performance do not share one meaningful review object or interval model. |
| D-037 | Stale evidence alone never constitutes regression. | `09-PROGRESSION.md` | Regression requires later admissible evidence showing current capability below threshold; staleness only requires refresh. |
| D-038 | Learner skipping, preference, or friction are planning signals, not ability evidence. | `01-LEARNER-MODEL.md`, `09-PROGRESSION.md` | Agency and adherence should shape eligible delivery choices without contaminating mastery inference. |
| D-039 | Full mocks are readiness/re-evidence activities with learning side-effects, not default learning mechanisms or certification shortcuts. | `07-PRACTICE.md`, `08-ASSESSMENT.md` | Broad integrated performance has value, but it cannot replace targeted intervention or claim-scoped sufficiency. |
| D-040 | Guided success and same-item retry preserve narrower inference scope than independent/unseen performance. | `08-ASSESSMENT.md`, `10-CONTENT-MODEL.md` | Scaffolding and exposure change what a performance can legitimately prove; they must be represented explicitly. |
| D-041 | Introduce a seven-document canonical `design/` plane downstream of learning specs. | `../CONSTITUTION.md` | User explicitly expanded the repository goal to include full learner flow, features, practice surfaces, media, API, and framework allocation. These are independent product/runtime authority domains and should not contaminate learning specs. |
| D-042 | The initial product surface contains 40 named feature capabilities: Listening 8, Reading 8, Writing 9, Speaking 9, Shared 6. | `../design/01-skill-features.md` | Concrete feature ownership prevents implementation teams from inventing inconsistent skill products while keeping features separate from Skill Leaves. |
| D-043 | The initial app exposes 28 user-facing practice modes: six per skill plus four shared. | `../design/02-practice-catalog.md` | Learners need an understandable concrete practice catalog; topic/source variants should compose modes rather than explode the taxonomy. |
| D-044 | YouTube/media is a source substrate, not another learning taxonomy; arbitrary unofficial YouTube download/transcription is not an assumed product capability. | `../design/03-media-youtube.md` | Parroto-like dictation/shadowing is useful, but official YouTube caption download and embedded-player policies impose real authorization/player constraints. |
| D-045 | The browser has one public product API through Go Core API; Python evaluator is internal only. | `../design/04-application-flows.md`, `../design/05-api.md` | One public boundary prevents TypeScript/Python/Go from independently orchestrating learner state or duplicating policy. |
| D-046 | Initial framework allocation is TypeScript/Next.js for web, Go `net/http` + chi for Core API, Python/FastAPI for evaluator/media analysis. | `../design/06-implementation-stack.md` | Each stack is assigned to the responsibility it fits; framework choice must not create duplicate semantic owners. |
| D-047 | Productive evaluation is asynchronous from the browser; Python returns bounded observations/provenance/uncertainty and Go applies Assessment/Progression. | `../design/04-application-flows.md`, `../design/06-implementation-stack.md` | Evaluation latency/failure must not block the browser indefinitely or let evaluator infrastructure become mastery authority. |
